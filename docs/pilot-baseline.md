# Пилот `tts assets audit`

## Цель

За один локальный запуск определить, какие внешние ресурсы упоминаются в
произвольном JSON-сейве Tabletop Simulator и какие из них доказуемо присутствуют
в локальном кэше.

## Интерфейс

```text
tts assets audit <save.json> [--mods-dir <path>] [--json]
```

Пилот поддерживает один файл. Обход каталогов, network check, скачивание,
backup, исправление URL и изменение сейва остаются вне scope.

## Результат

Для каждого уникального ресурса возвращаются:

- исходный URL;
- отсортированный список предполагаемых типов;
- список использований `{pointer, field, inferred_type}`;
- относительный путь локального файла, если найдено ровно одно доказуемое совпадение;
- метод и уровень уверенности сопоставления;
- один из статусов `cached`, `not_found_in_cache`, `unverified`.

Сводка содержит имя сейва, число объектов, Lua-скриптов, уникальных ресурсов и
счётчики по статусам и типам.

## Семантика статусов

- `cached`: локальный файл найден детерминированным правилом.
- `not_found_in_cache`: детерминированные правила не нашли файл в указанном
  кэше; доступность внешнего URL не проверялась.
- `unverified`: поле похоже на ресурс, но пилот не умеет надёжно определить его
  тип или ключ кэша, либо cache matcher нашёл несколько кандидатов.

## Exit codes

- `0`: аудит выполнен, все поддерживаемые ресурсы имеют статус `cached`.
- `1`: аудит выполнен, есть `not_found_in_cache` или `unverified`.
- `2`: неверные аргументы, файл не читается или JSON повреждён.
- `3`: внутренняя ошибка инструмента.

## Критерии приёмки

1. Один и тот же вход даёт байт-в-байт одинаковый JSON без временных полей.
2. Рекурсивно учитываются `ObjectStates`, `ContainedObjects` и `States`.
3. Поддерживаются как минимум изображения, модели, PDF, аудио и asset bundles.
4. Старые и новые Steam Cloud hostnames сопоставляются по каноническому ключу,
   а не простым сравнением полного URL.
5. Человекочитаемая сводка и JSON описывают одинаковые счётчики.
6. Тесты используют только синтетические fixtures; реальные Workshop JSON и
   ассеты не попадают в Git.
7. Локальная acceptance-проверка выполняется на Avalon, Clank! Catacombs и
   EPIC Terraforming Mars без изменения исходных файлов.

## Технический выбор для baseline

Python 3.12+, стандартная библиотека для ядра парсинга, `argparse` для первого
пилота и `pytest` для тестов. Дополнительная CLI-библиотека пока не оправдана:
интерфейс содержит одну команду, а минимальные зависимости упрощают публичную
установку и проверку.
