# Аналоги и свободная ниша

Дата проверки: 2026-08-30.

## Существующие проекты

| Проект | Основная функция | Лицензия | Что важно для `tts-cli` |
|---|---|---|---|
| [TTS Mod Vault](https://github.com/markomijic/TTS-Mod-Vault) | Кроссплатформенный GUI: download, backup, URL management, cleanup | GPL-3.0 | Активный широкий менеджер; не нужно повторять его GUI и bulk mutation |
| [ttsmutility](https://github.com/sharkusk/tts-mutility) | Python/Textual TUI, аудит и скачивание ресурсов, SHA1, поиск URL в Lua, virus scan | GPL-3.0 | Ближайший функциональный аналог, но ориентирован на интерактивный TUI |
| [tts-backup](https://github.com/eigengrau/tts-backup) | Python CLI для backup и prefetch, есть `--dry-run` | GPL-3.0 | Подтверждает ценность CLI, но его основной контракт — архивирование и загрузка |
| [TTS-Manager](https://github.com/cwoac/TTS-Manager) | CLI/GUI import-export в `.pak` | MIT | Проект сам обозначает ограниченное тестирование и alpha-качество |
| [ttsunhoster](https://github.com/theFroh/ttsunhoster) | Небольшой downloader/archiver Workshop-ресурсов | MIT | Хороший пример узкого инструмента, но он выполняет сетевую мутацию |

Официальная документация подтверждает, что локальные TTS-сейвы сериализуются в
JSON и содержат объектное дерево со ссылками на custom assets:
[Save File Format](https://kb.tabletopsimulator.com/custom-content/save-file-format/).
TTS кэширует загруженные ресурсы локально, а сторонние URL могут со временем
стать недоступны: [Asset Importing](https://kb.tabletopsimulator.com/custom-content/asset-importing/).

## Решение

Не строить ещё один backup/download/mod-manager. Свободная полезная ниша:

- маленький неинтерактивный CLI без GUI и локальной базы данных;
- read-only и offline-first поведение;
- устойчивый JSON-контракт для AI-агентов, CI и скриптов;
- путь до каждого упоминания ресурса внутри JSON;
- доказательство способа сопоставления с кэшем и уровень уверенности;
- честное различие между отсутствием в кэше и недоступностью в сети;
- детерминированный вывод и документированные exit codes.

Реализацию следует писать независимо по официальному формату TTS. Копирование
кода из GPL-3.0 проектов потребует GPL-совместимого лицензирования и в пилоте не
планируется.

## Публичность

Рекомендуемая последовательность:

1. Закрыть пилот локально на синтетических fixtures и нескольких реальных
   сейвах, не добавляя реальные сейвы в Git.
2. Провести проверку на утечки абсолютных путей, пользовательских данных и
   внешних URL из локальных модов.
3. Выбрать permissive-лицензию для независимо написанного кода и добавить
   уведомление, что проект не связан с Berserk Games.
4. Только после этого создать публичный GitHub remote.
